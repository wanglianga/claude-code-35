# 暖爪 · 城市宠物寄养试住评估与喂药记录平台

React 18 + TypeScript + Vite + Zustand 单页应用，Nginx 容器化部署。围绕「同一只宠物」打通：
**预约建档 → 试住评估分房 → 寄养照护时间线（喂食/喂药/遛狗/清洁/视频/异常）→ 喂药漏服补救（登记→店长复核→方案确认→调整用药时间→补服成功）→ 四方异常协同 → 班次交接 → 接回结算与护理交接摘要 → 下次接单风险提示**。

---

## 原始需求

> 设计城市宠物寄养试住评估与喂药记录页面，可使用 React、TypeScript 和 Zustand。宠物主人预约寄养时，页面收集宠物品种、年龄、疫苗、绝育、过敏、攻击性、分离焦虑、饮食习惯、用药和接送时间。门店安排试住时，工作人员记录宠物与其他动物互动、进食、排便、吠叫、抓挠和休息状态；试住结果决定能否接收、适合普通房、隔离房还是单独照护。寄养期间，工作人员按时间记录喂食、喂药、遛狗、清洁、视频回传和异常行为。若宠物拒食、呕吐、腹泻、咬伤员工、疫苗记录不全或主人临时延长寄养，页面要让店长、护理员、主人和合作医院围绕同一只宠物处理。接回时，寄养天数、加项服务、异常照护、赔付、押金和回访记录进入同一订单，方便主人后续追问。店长交接时可以看到每只宠物的当日风险摘要，下一班护理员不用从零翻看所有记录。异常宠物会进入下次接单风险提示。主人接回前，页面会生成护理交接摘要。页面还要让门店按宠物和房间查看风险，护理员交接时可以看到喂药、饮食、排便、互动和主人沟通的完整记录。

## 一键启动（Docker Compose）

```bash
# 环境变量由验证环境注入；本地自测可：
export CC_PUBLISH_PORT=3035
export COMPOSE_PROJECT_NAME=task2026-09-1235

docker compose up -d --build
```

- 仅应用服务（Nginx 静态站点，容器内 8080 端口）发布到宿主 `${CC_PUBLISH_PORT}`，**无数据库/缓存等依赖端口暴露**；本应用为纯前端 + localStorage 持久化，不依赖外部服务。
- 获取实际映射端口并访问：

```bash
docker compose port app 8080
# 浏览器打开 http://host.docker.internal:<映射端口>
# 健康检查：curl http://host.docker.internal:<映射端口>/healthz  → ok
```

停止与清理：

```bash
docker compose down
```

> Dockerfile 为多阶段构建（node:22-alpine 构建 → nginx:1.27-alpine 运行），
> 运行阶段以非 root 用户 `nginx` 启动，并内置 `HEALTHCHECK`（wget 探测 `/healthz`）。

## 演示数据动线（建议按此顺序体验）

1. **店长登录** → 总览看板：4 只在住/试住宠物、今日喂药执行表、未闭环异常、最新班次交接；风险按分数排序，**阿狼为高风险**。
2. **试住评估** → 选「豆豆（试住中）」：护理员可补录「互动/进食/排便/吠叫/抓挠/休息」六维 1–5 分观察；店长可看到系统房态建议并人工判定 → 分房 → 开始寄养。
   - **试住不通过处置（持续攻击/应激严重/拒食）**：试住页底部「🚫 试住不通过处置」中店长三选一：**拒收**（暂不接收）、**单独照护加价接收**、**建议医院检查**，并填写原因（永久写入宠物档案）、试住费收/免、押金退还额。提案后订单等待主人确认（主人可接受或提异议，异议后店长可改判），**主人确认后**：拒收单押金退还/试住费写入同一订单、订单置「试住拒收」、拒收原因写入宠物档案形成**硬性接单限制**；加价单自动转寄养并入账加价；医院检查单暂挂待复查。被拒收宠物再次预约时主人被拦截，仅店长可在核验（行为评估/补苗等）后强制覆核。种子宠物「坦克」（周先生）即已拒收案例：订单 b7 押金退 600、试住费免收，再预约会看到红色拒收史。

3. **照护记录** → 选「阿狼」：左侧今日用药提醒（漏服调整后：06:30 补服已成功 / 08:00 常规）与关联异常单，右侧喂食/喂药/遛狗/清洁/视频/异常/主人沟通完整时间线；护理员可「＋ 新增照护记录」，勾选异常类型（拒食/呕吐/腹泻/咬伤员工/疫苗不全/延长寄养）会自动开异常协同单并按类型拉对应角色入伙。
   - **喂药漏服补救（重点演示）**：点「⚠ 登记喂药漏服/吐药」→ 选药品、计划/发现时间、原因（漏服/吐出药片/服药后呕吐/拒服）与宠物状态，并勾选是否联系主人/兽医；系统按原因与药品（服药后呕吐、抗生素/处方类）建议严重度。**严重漏服自动进入店长复核并生成高严重度异常协同单**（店长/护理员/主人/医院）。店长复核通过后，护理员确认补救方案：补服（不双倍）/跳次/按兽医指导，填写**给主人的新喂药说明**，设定**调整后的补服日期时间**（如今晚 20:00 漏服 → 明晨 06:30 补服），**下一班提醒频率随原因变化**（服药后呕吐→夜班每 2 小时巡视+给药后留观 30 分钟）。到点执行后点「✓ 已补服成功」，总览喂药表、照护页提醒与班次交接同步显示「已补服成功」；接回结算时仍有待复核/待补服的漏服会拦截闭环；主人端与护理交接摘要可查看新喂药说明。
   - 种子数据：奶茶 9/11 关节保普通漏服（方案已确认、今日 08:00→09:30 待补服，主人可见说明）；阿狼 9/11 晚蒙脱石散服药后呕吐（严重→店长复核→医院指导→9/12 06:30 已补服成功，含完整四方协同记录 inc5，异常单已同步闭环）。
   - **时间与时区**：全系统统一使用「门店本地挂钟时间」（naive local，存储串不带时区后缀），护理员输入的 08:00 在时间线、补救方案、主人说明、当日/跨日提醒中始终是同一个时间，不受浏览器或容器时区影响（已在 Asia/Shanghai、UTC、America/New_York 三种时区下跑同一动线验证）。服药后呕吐/吐药的补服强制安排在**次日**（UI 与存储层双重校验，不得提前到当天）。**补服到点门禁**：补服标记成功的执行时间不得早于补救方案的日期时间（次日 06:30 的补服在当天或 06:29 前点击成功均被拒绝，且不产生照护事件、不闭环异常）；补服成功事件与常规剂量区分，不会把常规范次误标为已喂。**状态联动**：严重漏服复核通过后异常单转「处理中」，到点补服成功或店长判定跳次后关联异常单才自动闭环并留痕——异常协同页不再残留「待店长复核/异常处理中」。
4. **异常协同** →「阿狼护食扑咬」单：店长/护理员/主人/医院四方留痕，医院已给出 III 级暴露意见，店长可闭环；用 `hospital` 登录可追加医疗意见，用 `zhou` 登录可确认延长寄养（自动给订单加费）。
5. **房间风险看板**：普通房/隔离房/单独照护间三栏按房查看，或切到「按宠物风险」排序；底部展示阿狼历史订单的「下次接单风险提示」。
6. **班次交接**：每只宠物的当日摘要（喂药 ✓/待喂、饮食、排便、互动遛放、视频、主人沟通、异常），高风险在前；店长可发布白/夜班交接。
7. **接回结算**（店长）：寄养天数自动按实际送达/接回计算，可增加加项服务、异常照护、负数赔付行，押金自动抵扣；编辑自动生成的护理交接摘要、勾选下次接单风险、记录回访后闭环订单。
8. **护理交接摘要**（主人 `owner` / `zhou` 登录）：查看/打印本次寄养摘要、费用明细、回访与下次风险提示；已闭环的阿狼历史订单（含 -¥200 赔付、延长 1 晚、回访）可完整追溯。
9. **预约登记**（主人或店长）：完整收集品种、年龄、疫苗（可逐项勾选有效期）、绝育、过敏、攻击性、分离焦虑、饮食、多条用药（剂量/方式/时间点）、接送时间；疫苗全不勾选提交时会弹风险确认。

## 技术说明

- `src/types.ts`：领域模型（预约资料 / 试住观察、结论与不通过处置 / 照护事件 / 异常协同单 / 房间 / 订单费用 / 回访 / 班次交接 / 喂药漏服补救 / 宠物拒收史）。
- `src/store.ts`：Zustand store + `persist` 中间件（localStorage 持久化，v2，刷新不丢数据），含全部业务动作与选择器（`effectiveMedPlan` 统一计算套用漏服补救调整后的当日喂药提醒，`isPetBlocked/petBlockingRejections` 提供再次接单限制）；侧栏「恢复演示数据」可一键重置。
- `src/lib/risk.ts`：风险评分规则（疫苗缺失 +3、中重度攻击性 +3、分离焦虑、过敏、试住维度最差分、未闭环异常、历史风险标记），并据此给出试住房态建议。
- `src/pages/`：Login、Dashboard、Bookings、BookingForm、TrialEvaluation、CareTimeline、Incidents、RoomRisk、ShiftHandover、Checkout、OwnerSummary 共 11 个页面，按角色显示导航与操作权限。
- 纯前端工程，无后端依赖；视频回传字段为演示占位链接。
